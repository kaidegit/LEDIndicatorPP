# 行为契约与归属

## 时间

- `start` 不立即写驱动；首次 `update` 执行第一步。`start` 与重复 `start` 都把步骤、累计时间清零，并以当前 `uint32_t` 时间为起点。
- 场景时间为安全整数毫秒，跨组件边界时取低 32 位。无符号减法定义回绕行为。
- `advance` 只改时钟，`update` 才执行更新；同一时刻操作严格按数组顺序执行。
- 所有活动 pattern 都推进，非最高优先级不写输出。

## 输出与恢复

- 数值较小的 type 优先。活动列表为空时不主动增加 OFF/CLEAR 请求，保持既有驱动输出。
- 最高优先级结束后，先恢复下一个活动 pattern 最近一次 RGB/IRGB 缓存，再执行它当前步骤；这与现有恢复路径一致，但回归比较仍同时检查实际输出，不把源码当作唯一判据。
- 运行中重新注册不会主动重置活动状态。索引越界、空步骤、无终止步骤与零时长循环属于鲁棒性探测；工具报告 trap、timeout 或 OOM，不把它们判成支持。
- HSV、BREATHE 渐变和驱动未实现的接口标为 `unsupported`。RGB 的颜色请求与实际引脚事件分别比较。
- RGB 驱动缓存初始为白色，独立于初始为空的颜色请求记录；仅 RGB 颜色请求更新该驱动缓存。断言失败不会被 `unsupported` 状态覆盖。

这些规则只描述测试模型，没有修改组件在边界条件下的既有用户可见行为。后续若要改变替换、恢复或结束后关灯语义，需要先更新契约与场景。

## 内存归属与口径

- WASM 中的组件对象、驱动、pattern 和容器使用同一份静态 backing 上的 TLSF 固定池；耗尽不回退到 Emscripten 堆。
- 场景 JSON、断言、JS 报告在宿主分配；事件、状态、输入和块快照使用适配层静态数组，不计入组件池。
- 分配序号从实例创建开始，第 N 次包含实例和驱动的分配。失败记录操作种类与操作索引。
- 实际池占用为 TLSF 返回的块大小之和；请求字节不含 Header、红区和对齐。固定开销单列 `allocatorOverheadBytes`。
- 碎片率为 `(1 - largestFreeBlock / freeBytes) * 100`，无空闲块时为 0。诊断遍历不进入基准热路径。
- 静态 backing 属于 WASM 静态区，不与线性内存重复相加。Data section 体积不是运行时 RAM。栈高水位若未可靠实现则为 `null`，Node/浏览器/JIT 内存不属于组件 RAM。
- `physicalPoolBytes` 是固定 backing 预留量（1 MiB）；`configuredBytes` 是本次可供 TLSF 管理的容量，二者与池内使用量分别报告，不重复计数。
- Memory-check 始终提供 16 字节红区、释放填充和 TLSF 一致性检查；不宣称等价于完整 ASan。
- 所有配置使用原生 WASM exceptions。1024 字节静态异常应急区只用于在池耗尽时完成 `std::bad_alloc` 抛出；它不支持并发异常，也不是默认堆回退，开销计入固定成本。
